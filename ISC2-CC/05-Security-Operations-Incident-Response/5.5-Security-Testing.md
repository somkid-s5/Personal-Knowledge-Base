## Purpose

security testing ตรวจว่า controls/defenses ทำงานจริงหรือมี weakness ก่อน attacker ใช้

testing ต้องมี authorization และ scope

## Blue, Red and Purple teams

### Blue team

defend, monitor, detect, investigate และ respond

### Red team

authorized adversary simulation เพื่อทดสอบ people/process/technology ตาม scope

### Purple team

red + blue collaboration เพื่อเรียนรู้และปรับ detection/defense เร็วขึ้น

Purple team ไม่จำเป็นต้องเป็นทีมถาวร แก่นคือ collaboration

## Vulnerability scanning

automated identification of known/suspected weaknesses เช่น outdated software, exposed services หรือ misconfiguration

scan result ต้อง validate/contextualize

scanner finding ≠ confirmed exploitability เสมอ

## Static analysis (SAST)

วิเคราะห์ source/code/binary โดยไม่รัน application

เหมาะกับ finding classes ที่เห็นจาก code structure

## Dynamic analysis (DAST)

ทดสอบ running application จากภายนอกเหมือน interaction จริง

เห็น runtime behavior แต่ visibility ภายใน code ต่ำกว่า SAST

## Threat modeling

คิดล่วงหน้าว่า:

- assets คืออะไร
- trust boundaries อยู่ไหน
- attacker ทำอะไรได้
- abuse cases คืออะไร
- mitigations อะไรจำเป็น

ทำได้ตั้งแต่ design stage จึงช่วยป้องกันก่อน deploy

## Physical penetration testing

current objective ยกตัวอย่าง:

### Phishing

ทดสอบว่าคนเปิดเผย credential/click/execute หรือ report อย่างถูกต้องหรือไม่

### Tailgating

พยายามตามผู้มีสิทธิ์เข้า restricted area

### Impersonation

ปลอมเป็น staff/vendor/authority เพื่อ bypass process

ทุก test ต้อง authorized และมี safety boundary

## Testing vs production damage

security test ไม่ควรกลายเป็น incident เพราะไม่มี scope

ก่อน test ต้องรู้:

- authorization
- target
- time window
- prohibited actions
- stop condition
- communication/escalation

## AI and security testing

AI-integrated application ยังต้อง vulnerability testing, threat modeling และ readiness testing

AI อาจเพิ่ม abuse cases เช่น prompt injection, sensitive-data exposure หรือ excessive agent permissions แต่ fundamentals ของ scope/evidence/authorization ยังเหมือนเดิม

## Scenario

scanner พบ critical CVE บน Internet-facing server

ขั้นต่อไปไม่ใช่ assume compromise แต่ validate asset/version/exposure, prioritize และ remediate ตาม risk

## Common traps

| Trap | Correct mental model |
|---|---|
| Red team = vulnerability scanner | red team simulates adversary objectives |
| Purple = third opposing team | collaboration of offensive/defensive learning |
| SAST = running app test | SAST analyzes code without execution |
| DAST = source review | DAST tests running app |
| Scan finding = incident | finding needs validation/context |
| Pen test without written scope | unauthorized activity risk |

## Knowledge check

1. Blue/Red/Purple ต่างกันอย่างไร?
2. scanning ต่างจาก penetration testing อย่างไร?
3. SAST/DAST ต่างกันอย่างไร?
4. threat modeling ควรเริ่มเมื่อไร?
5. physical penetration testing มีตัวอย่างอะไรบ้าง?
