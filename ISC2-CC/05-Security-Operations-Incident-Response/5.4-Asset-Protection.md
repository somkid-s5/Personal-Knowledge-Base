# 5.4 — Understand Asset Protection

[← Domain 5](./README.md)

## Asset lifecycle

asset security ต้องครอบคลุมตั้งแต่ acquire → deploy → operate → maintain → retire/dispose

สิ่งที่ไม่มี inventory มักไม่ได้ patch, review หรือ retire อย่างถูกต้อง

## End of Life (EOL)

EOL asset มี risk เพราะ:

- vendor patch หยุด
- support หาย
- compatibility กับ controls ใหม่ลดลง
- known vulnerabilities สะสม

treatment อาจเป็น:

- upgrade
- replace
- isolate
- restrict access
- compensating controls
- retire

## Configuration management

ตอบคำถาม:

> asset ที่ปลอดภัย “ควรมีสภาพอย่างไรตอนนี้?”

ใช้ baseline เพื่อ:

- standardize settings
- detect drift
- harden
- document expected state

ตัวอย่าง:

- unnecessary ports closed
- unused accounts removed
- approved services only
- secure settings
- current patches

## Change management

ตอบคำถาม:

> จะเปลี่ยนจาก current state ไป new state อย่างปลอดภัยอย่างไร?

flow:

~~~text
request
→ assess risk/impact
→ approve
→ test
→ schedule/communicate
→ implement
→ verify
→ rollback if needed
→ document
~~~

## Configuration vs Change management

| Configuration | Change |
|---|---|
| desired/current state | transition between states |
| baseline | approval/testing/rollback |
| detect drift | control change risk |

## Patch management

patching เป็นส่วนหนึ่งของ asset/configuration protection

ต้อง balance:

- vulnerability risk
- compatibility
- test
- rollout
- rollback
- criticality

## AI assets

asset inventory ควรรวม AI services, models, agents, datasets, API integrations และ credentials

EOL/unsupported model/tool ก็เป็น lifecycle risk เช่นเดียวกับ software อื่น

## Scenario

legacy server หมด vendor support แต่ยังต้องใช้ 6 เดือน

อย่าปล่อย unchanged

ใช้ isolation, stricter access, monitoring, compensating controls และ formal replacement plan
